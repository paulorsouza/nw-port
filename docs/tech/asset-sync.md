# Asset sync between machines

Import once on one machine and carry the result to your other machines (Linux ↔ Windows, Windows ↔ Windows), or
keep it as a backup for when you reinstall the disk. Code stays on GitHub. What git does not carry goes as zips
through a folder that you sync yourself. Scripts: `tools/assets_export.py` and `tools/assets_import.py`.

## Purpose

- This is a backup of **your own** imported assets, for **your own** machines.
- Never use it to share game content with other people. Each person extracts from their own New World install
  ([../setup.md](../setup.md)).
- Storage can be any folder you sync between your machines: a cloud drive (OneDrive is one option), an external disk,
  a NAS. Upload and download are done by hand; the scripts only read and write the local folder.

## What goes and what does not

| Folder | Goes? | Why |
|---|---|---|
| `unreal/NWPort/Content` (except the files tracked in git) | yes | Import result. `.uasset`/`.umap` are identical on Linux and Windows for the same Unreal version. |
| `unreal/NWPort/Data` | yes | Generated by the `make_*.py` scripts. |
| List of `extract/.etapas/ue_*.ok` | yes, inside the manifest | The other machine does not redo in `ue_import_all.sh` an import that arrived ready. |
| `extract/` | no | Only needed to import again or convert something new. Each machine extracts its own. |
| `DerivedDataCache`, `Intermediate`, `Saved`, `Binaries` | no | Platform dependent. Each machine rebuilds them. |
| `ABP_NW.uasset`, `ABP_Lost.uasset` | no | They are in git. |

## The folder

Each machine has a local folder that mirrors the synced one. Default `~/nw-port-assets` (on Windows
`C:\Users\<user>\nw-port-assets`). Another location with `--dir` or `NW_ASSETS` (also settable in `local.env`).

```
nw-port-assets/
  manifest.json      generation, id, machine, date, commit, Unreal version, game build, markers, zip list
  bundles/*.zip      one zip per Content folder, up to 1 GiB each
```

The zip name includes the content hash (`Content__NW__Region__06sw02_cascadeharbor_props-1a2b3c4d5e6f.zip`), so a
new zip never has the name of an old one. Size of a full set: [../notes/windows.md](../notes/windows.md).

## Export (end of day, on the machine that imported)

1. Editor closed. Code committed and on GitHub.
2. Copy the latest `manifest.json` from the synced storage into the folder. If another machine exported after your
   last import, the export stops and asks you to import first.
3. Run:

   ```bash
   python3 tools/assets_export.py
   ```

   Windows: `py tools\assets_export.py`.

4. The script lists what to upload and what to delete. Upload the new zips to `bundles/` in the synced storage and,
   last, the `manifest.json`. Then delete from the storage the zips it told you to delete.

The first time, upload everything: the whole `bundles/` folder and the `manifest.json`.

## Import (on the other machine)

1. Editor closed. `git pull`.
2. Copy only the `manifest.json` from the synced storage into the folder and run:

   ```bash
   python3 tools/assets_import.py
   ```

3. The script compares with the local files and lists the missing zips (exit code 2). Download those zips into
   `bundles/` (or loose in the folder) and run again.
4. It checks the sha256 of each zip, shows the summary and asks. Once applied, the machine is at the generation of
   that publication.

The first time, download the whole `bundles/` folder.

`--check` only shows what would change. `--yes` does not ask.

After the import, open the editor: Unreal compiles the shaders of the changed assets on first open.

## What the scripts check

Export:

- Editor closed. On Linux it enters the `tools/linux/pesado.sh` queue.
- Current commit is on GitHub and nothing is uncommitted in `unreal/NWPort/Source`, `Config`, `.uproject` or `tools/`
  (`--allow-dirty` overrides).
- The `manifest.json` in the folder is the publication this machine has (exported or imported last). If not, another
  machine exported later: import first, or `--force` to discard that machine's publication.
- Same Unreal version.
- Names that work on Windows and cloud drives (case, characters, reserved names, path up to 240 from `C:\nw-port`).
- Fewer than half the files of the current publication (fresh clone, deleted folder): it stops.
- Nothing changed: no new generation is created.

Import:

- Same Unreal version, same game build (`tools/jogo.versao`), commit of the publication already in the local `HEAD`
  (`--force` overrides).
- Size and sha256 of each zip against the manifest (an incomplete download is not applied).
- A zip only extracts inside its own folder.
- A local file that is replaced, or that is not in the publication, goes to
  `unreal/NWPort/Saved/assets_backup/<data>/` (the last 3 are kept). Files tracked in git are not touched.

## Rules

- One machine imports at a time. If two machines import on the same day, the second to export is blocked and
  chooses: import and redo its own import, or `--force`.
- Always copy the newest `manifest.json` before exporting or importing.
- Use `--force` only when the owner of the machines asks for it: it discards the other machine's publication.
- Uncommitted changes from other areas in `Source/` or `tools/`: ask the owner of the machines before exporting with
  `--allow-dirty`.
- An Unreal reimport rewrites the `.uasset` even without a real change, so a reimported folder produces a new zip.
- Machine state in `unreal/NWPort/Saved/assets_state.json`; cached hashes in `assets_hashcache.json` (only changed
  files are read again; the first read of the whole Content takes about 2 min).

## Windows

- Python: `winget install Python.Python.3.13`.
- Unreal outside `C:\Program Files\Epic Games\UE_5.*`: set `NW_UE`.
- Pipeline in WSL: `$env:NW_EXTRACT = "\\wsl$\Ubuntu\home\<user>\nw-port\extract"` so the markers go to the WSL
  `extract/`.
